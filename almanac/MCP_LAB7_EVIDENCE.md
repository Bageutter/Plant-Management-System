SQLite catalogue. This is project evidence, not an assessment-completion claim.
Reproduction commands and source links are in [MCP.md](MCP.md).

## Execute and observe

The current scope has three tools: `search_catalogue`, `get_plant` and `get_problem`.
The collector makes six real stdio calls: search Lettuce → get plant; search Aphids
→ get pest; search Powdery mildew → get disease. The harvest-space calculator has
been removed from the app, API and MCP tool list. Descriptive catalogue data remains.

disabled the Run button when switched off, displayed a missing-plant tool error,
and recovered with a valid Lettuce lookup. The displayed results are deterministic
tool outputs, not model-generated advice. Raw inputs/results/timing are expandable.

## Historical review, defect, improvement and retest

The following model runs were captured before the scope reduction. Their original
raw evidence is preserved unchanged; they are evidence of the guide-claim defect
and safeguard, not new model reviews of the reduced three-tool implementation.
Fresh execution evidence for the current scope is generated by the collector and CI.

| Run ID | Models and observed outcome |
| --- | --- |
| `2776d7a5-d41a-42e8-b2cb-867e9273fe9b` | Initial Qwen2.5 0.5B proposal incorrectly claimed management guides were absent; Llama3.1 8B approved it. Agent inspection rejected that conclusion against the actual outputs. |
| `0d14a06a-dbae-42c2-b6a5-fbaf742801d4` | After improvement, the same small proposer invented guide call IDs. Deterministic validation rejected them; a second proposal had correct IDs but an unsupported claim, which Llama rejected. Final status: `needs_revision`; command exited 1. |
| `89874939-55d9-43b6-a634-5c3836e7f2d6` | Explicitly selected installed Qwen3 4B with Llama3.1 8B. Interpretation acknowledged both guides and estimate limitations; checks and reviewer passed. Final status: `model_approved`; human decision still pending. |

The concrete improvement was to include guide context in the compact evidence,
require structured guide-availability claims, compare every claim/ID to actual tool
output **before** review, and teach the reviewer to challenge negative claims.
Two attempts maximum prevent indefinite retrying until a model agrees.
The regression test deliberately supplies a false unavailable-guide claim and
asserts rejection before a reviewer can approve it.

This does not prove all free-text claims are correct. Model agreement is advisory;
human review of the original evidence remains required. The first run demonstrates
why two models alone are insufficient.

## Validation layers

- Backend: API boundaries plus real stdio and Streamable HTTP discovery/invocation.
- UI: actual MCP calls, CSRF, disabled mode, invalid inputs, escaped results/errors,
  unavailable adapter, estimate labels and proxy-aware guide links.
- Pipeline: live evidence collection; saved reports; offline/discovery failures;
  schema/ID/guide guards; bounded revision; model failure; no inferred human approval.
- Existing development scopes remain unchanged; the MCP dispatcher propagates the
  collector/review status without opening an unrelated interactive code-review flow.

Raw per-run evidence is local under ignored `.ai-dev-runs/mcp/<run-id>/` rather than
committed wholesale. CI independently recreates tool-execution evidence and uploads
it as `almanac-mcp-evidence`. CI does not run or claim model review. Docker builds
and full-stack checks remain separate evidence from these local runs.
